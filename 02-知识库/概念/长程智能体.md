# 长程智能体

> 长程智能体是能够连续运行数小时或数天的 AI agent；它的难点不只是模型能力，而是上下文、规划、验证、状态和可观测性的系统设计。

## 核心内容

[[Anthropic团队：如何构建运行 数小时的Agent]] 把长程智能体的失败拆成三类：context、planning、self-evaluation。上下文窗口会失忆、腐化或在末尾焦虑；规划会 one-shot 过载、半途停工或留下半成品；自我评价会把看起来完成的 UI 当成真实功能完成。

长程智能体需要 [[Agent Harness]]。这个 harness 至少包括：

- 持久化状态：feature list、progress file、contract、time log、trace、docs；
- 独立验证：用 [[生成器-评估器架构]] 让 evaluator 真正操作产物；
- 完成契约：把模糊 user story 转成可测试 criteria；
- 可观测性：把运行轨迹当 stack trace 读；
- 版本控制：commits、pull requests、Git worktrees，避免多 agent 覆盖同一文件系统。

## 与短任务 agent 的区别

短任务 agent 可以依赖一次上下文和最终回答。长程智能体必须跨越多个阶段、多个判断和多个失败路径。它的“记忆”不应只放在模型 context 里，而要外部化到 [[文件系统共享状态]]。

## 待继续研究

- 哪些任务适合 single continuous session + compaction，哪些仍需要 fresh context / RALPH 风格切分？
- 长程 agent 的 observability 应如何设计，才能让人类快速定位偏航点？
- human-in-the-loop 是稳定性补丁，还是应被吸收到 harness 的 prompt、rubric、skills 中？
