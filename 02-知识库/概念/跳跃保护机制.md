# 跳跃保护机制

> 玩家想跳到边缘，手抖早按了零点几秒，角色直直落下去。他认为是自己操作失误，其实是设计没有替他兜住。这个兜底从马里奥 64 就有了，叫跳跃保护。不做这一层，所有跳跃都变成考试。

## 什么是跳跃保护

跳跃保护指一系列让「接近成功的跳跃」变成成功的容错设计。

典型机制：

- **边缘角度修正。** 玩家朝平台边缘跳跃，实际落点略微向内偏，把「擦边」变成「站上」。
- **土狼时间（coyote time）。** 走出平台边缘后仍有几十毫秒可以起跳。
- **输入缓冲（jump buffering）。** 落地前提前按跳，落地瞬间自动执行。
- **落点吸附。** 靠近边缘时角色被吸向平台。

这四项里，马里奥 64 已经成体系地做了前两项的近亲——脚下的固定阴影（不随光源，用来判断落点）和边缘自动抓取（差一点也抓住、滑落时也能抓住），宫本茂在官方攻略本里也说过关卡是按「跳得差不多就算过」设计的。土狼时间与输入缓冲是后来才被命名并标准化的。四项合起来，构成 3D 平台游戏的标准配置。它们不降低难度设计，只是把「操作精度」与「判断精度」分开——玩家判断对了，就不该因为手抖失败。

## 最后的守护者的失败

necromanov 的批评很具体：主角永远向正前方起跳，没有边缘角度修正。「手抖按跳进度就完」。

叠加因素让问题放大：

- 低帧数。PS4 版仍掉帧，而无保护设计在低帧下变成重试地狱。
- 动画前摇过长。小男孩的动作前摇约为神秘海域德雷克的两到三倍。
- 敌人擒抱与光束带来的迟钝 Debuff。前摇加 Debuff 形成 1+1<2 的效果。

三者叠加，把一个「容错问题」变成了「体验破坏」。玩家不是在挑战谜题，是在和操作较劲。

## 为什么这是「过时」而不是「硬派」

区分标准很清楚：

**硬派**是判断难——要求玩家看懂局势、想对解法。**过时**是执行难——要求玩家手稳、反应快。

跳跃保护属于后者。它不改变谜题的解法，只改变执行的成功率。去掉它不会让游戏更有深度，只会让失败的原因变得不清晰。

这一点和 [[西洋动作游戏设计]] 里的「输入有效时间」是同一个问题的两面：都是把玩家的意图准确翻译成系统动作。

## 与其他容错设计的对照

游戏里有大量同类机制，都在做同一件事——把「差一点」变成「成了」：

| 机制 | 兜住的是什么 |
| --- | --- |
| 跳跃保护 | 起跳时机与落点的微小偏差 |
| 输入缓冲 | 按键时机与动作窗口的错位 |
| 自动瞄准辅助 | 瞄准精度的不足 |
| 连招宽容窗口 | 节奏的微小偏差 |
| 避免即死 | 单次失误的后果过重 |
| 存档点密度 | 重试成本过高 |

共同的设计意图是：**让玩家失败时知道为什么失败。** 如果失败原因是「我不知道为什么」，那就不是难度，是噪音。

## 什么时候不该做

有两种情况需要谨慎：

**情况一：跳跃本身就是玩法核心。** 精确平台跳跃（如蔚蓝的 B 面）以操作精度为乐趣来源，过强的保护会消灭乐趣。这类游戏的做法通常是保留保护但提高关卡要求。

**情况二：保护机制本身可被利用。** 有些保护会被玩家用来跳过设计意图（用土狼时间跨越本不该跨越的缝隙）。这需要与关卡设计配合。

两种情况的共同点：**保护是默认该有的，去掉需要理由。** 反过来（默认没有，加了算加分）是设计观念的落后。

## 检查清单

- 有边缘角度修正吗。
- 有土狼时间与输入缓冲吗。
- 帧数是否稳定，低帧下保护是否仍有效。
- 动画前摇是否过长。
- 失败时玩家能否明确知道原因。
- 去掉保护是否有明确的设计理由。

- ~~马里奥 64 是否是跳跃保护的最早实现需核实（可能有更早的 3D 平台游戏）。~~ 已核实（2026-11-05）：应改为「最早成体系实现」而非「最早实现」。可查证的是马里奥 64（1996-06-23 日本）确实做了一整套兜底：脚下的固定阴影（不随光源，用于判断落点）、边缘自动抓取（差一点也会抓住，滑落时也能抓住）、以及宫本茂在官方攻略本里说的「关卡按『跳得差不多就算过』来设计」。更早的真 3D 平台游戏存在（1994 年 X68000 的 Geograph Seal、1995-04 的 Jumping Flash!），但没有任何资料显示它们实现了同类容错。土狼时间与输入缓冲这两个具体术语是后来的叫法，当时并无此命名。
