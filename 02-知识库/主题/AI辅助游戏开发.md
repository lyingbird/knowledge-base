# AI辅助游戏开发

> 用 AI（Chat 型大模型 / 桌面型编程 agent / MCP 桥接）把"做游戏"的门槛拉低到"会描述需求"：开发者从写代码转向当产品经理/策划，AI 接管代码与实现。这是 [[AI游戏与虚拟世界]] 主题在**个人/独立开发者实操层**的延伸。

## 核心判断

[[AI游戏与虚拟世界]] 已有两条线——游戏作为 AI 能力试验场、工作室把 AI 放进生产管线提效（[[游戏工作室AI提效落地框架]]）。本主题补上**第三条线：个人开发者用通用 AI 工具直接做游戏**。2026-06-30 导入的一组 [[Roblox Studio]] 视频显示：一个不会写 Luau 的人，靠 AI 就能做出可玩的小功能乃至完整游戏原型。

把这些素材放在一起可得一个清晰图景：**"AI 当生产工具"已能落地，"AI 当运行时世界生成器"仍是 demo**。

## AI 接入游戏开发的三条路径

| 路径 | 形态 | AI 角色 | 代表素材 |
|---|---|---|---|
| Chat 型 AI | 自然语言 → 出代码 → 人手动粘贴 | 顾问/向导，不碰项目 | [[不用再学代码了！零基础AI全自动做Roblox游戏教程]]（[[DeepSeek]] 段） |
| 桌面型 agent + 文件同步 | AI 直接读写本地文件，经 [[Script Sync]]/[[Rojo]] 同步进 Studio | 接管代码库，自动新建/改/删脚本 | [[不用再学代码了！零基础AI全自动做Roblox游戏教程]]（[[Claude Code]] 段）、[[【中配】用AI制作罗布乐思爆款游戏 其实很简单 - tef]] |
| [[Model Context Protocol]] 桥接 | Claude Desktop 经官方插件直接操作 Studio 对象树 | 直接接管创作工具本身 | [[Roblox Studio 接入 Claude MCP：自动生成游戏内 GUI 系统]] |

## 可复用方法

- **角色转换**：把自己当产品经理/策划/测试员——描述"要什么效果、哪里有问题"，而非"代码怎么写"。
- **里程碑式 vibe coding**：把整款游戏拆成里程碑（框架→战斗→任务→世界/属性），每步做完即时进游戏测试、以玩家反馈驱动迭代（[[【中配】用AI制作罗布乐思爆款游戏 其实很简单 - tef]] 的完整示范）。
- **同步管线是关键**：让 AI 改的代码进 Studio，需要 [[Script Sync]]（官方）或 [[Rojo]]（社区）；UI 等不同对象路径要分别同步。
- **代码生成 UI**：Roblox 脚本可用代码创建 UI，无需手拼（[[Claude Code]] 生成 GameOver UI / [[Model Context Protocol|MCP]] 生成 HUD/地图/背包）。
- **已知摩擦**：模型对 Luau 支持参差（[[DeepSeek]] 反复报错需人工修 animation id）、同步权限/版本不一致报错、Claude 使用额度限制、世界场景摆放仍需手动。

## 平台级 AI 生成游戏（对照面）

[[竟然已经可以游玩了？Roblox AI渲染游戏【Roblox新闻】]] 是 Roblox 平台自己推的"AI 实时生成/渲染整个可玩世界"research preview 的实测：概念上属 [[AI原生游戏]]，但画面糊、操作失灵、场景消失、好评率 3%。它和上面"AI 当生产工具"的成熟度形成强烈对比，也呼应 [[游戏工作室AI提效落地框架]] 的结论——AI 在游戏里最稳的价值在生产环节，端到端实时生成可玩世界仍不可外推为成熟生产力。

## 待继续研究

- 多人联机同步、数据存储、复杂 UI 等"真实项目"需求，AI 工具链能做到什么程度（多位 UP 均把这些留作后续）。
- 不同模型（DeepSeek / Claude / Gemini 等）对 Luau 与 Roblox API 的实际能力差异。
- 同步管线（Script Sync vs Rojo）与 MCP 桥接在复杂项目中的稳定性与协作方式。
- "AI 生成可玩世界"从 demo 到可玩，缺的是行为闭环（操作/碰撞/场景持久性）而非画面。
