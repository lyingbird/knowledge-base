# 生成器-评估器架构

> 生成器-评估器架构把 builder 和 critic 拆成独立上下文，通过对抗压力减少自评偏差，并把“完成”转成可测试契约。

## 核心内容

在 [[Anthropic团队：如何构建运行 数小时的Agent]] 中，Ash 把这种结构类比为 GAN：Generator 负责 build，Evaluator 负责 grade。Evaluator 不只是读 diff，而是用 Playwright 或 Chrome MCP 打开真实页面、点击、截图、检查 network/console errors，再把 critique 交回 generator。

这种架构利用一个非对称性：独立 critic 比 builder 更容易调得严厉。让同一个 agent 写完后自查，常会 rubber stamp；让另一个 context window 中的 evaluator 按 rubric 和 contract 检查，更容易发现“按钮存在但后端不存在”“游戏界面存在但不能玩”这类表面完成。

## Completion Contract

写代码前，Generator 先提出要做的 feature 和验证方式；Evaluator 反驳 scope 太大、test 太弱、漏 edge cases；双方通过磁盘文件往返，直到达成完成契约。之后 evaluator 按 contract 而不是最初模糊 spec 评分。

Retro Forge demo 最终形成 27 条 contract criteria。这个细粒度让反馈变得 actionable，而不是“做得更好”这种无法修复的泛泛 critique。

## 可扩展形态

这个模式不必只有一对 generator/evaluator。一个长流程可以让 dataset generator、backend builder、frontend builder、integrator 各自配独立 critic。关键是在每个产生 artifact 的环节加入对抗性检查。
