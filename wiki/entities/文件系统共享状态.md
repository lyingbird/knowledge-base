# 文件系统共享状态

> 文件系统共享状态是把长程 agent 的记忆、进度、契约、日志和交接线索写入磁盘，而不是只依赖上下文窗口或有损摘要。

## 核心内容

[[Anthropic团队：如何构建运行 数小时的Agent]] 反复强调，compaction 不等于 coherence，lossy summaries 会漂移。长程 agent 更适合把关键状态写进文件系统，让下一个模型、人类开发者或另一个 agent 可以 grep、阅读并接上进度。

推荐保存的内容包括：

- feature list、progress file、完成 flags；
- completion contract、test criteria、rubric；
- 尝试过什么、如何评估、发现什么 bug；
- 实现了什么 fix、fix 是否有效、最终状态；
- timestamped time log；
- live-updating docs 和高层 file structure。

## 与团队协作的关系

当多个 agent 或多人并行时，文件系统状态还需要 version control、commits、pull requests 和 Git worktrees。它们不是 AI 特有工具，却是防止多个 agent 覆盖同一工作区、让人类 review 和 merge 的成熟机制。

## 边界

“模型不太会覆盖 JSON 文件”是视频中的经验观察，不应升级为通用规律。更稳妥的原则是：关键状态要结构化、可 diff、可回滚，并进入版本控制。
