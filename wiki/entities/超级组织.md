# 超级组织

> 超级组织是出门问问 CEO 李志飞提出的判断：当 AI 把个体能力放大后，组织需要被重新设计以承接这种新生产力——核心是把"沟通"与"执行"合二为一，让 Agent 接管中层的转译与协调。

## 提出背景

李志飞从自己做 AI coding（用 AI 从零搭仿飞书协作产品原型）的体验倒逼出这个判断：AI 已重构个人生产力，但能否重构组织生产关系？

核心矛盾：**个体变强未必等于公司变强。"组织从来不是单纯的能力总和，而是协作效率总和。"** [[AI超级个体]] 的个人英雄主义进入组织反而可能是灾难——文件在本地、密钥硬写、流程只在一个人脑子里，一进组织全部失效。

## 解法：沟通与执行合二为一

- 传统协作工具把沟通与执行分开（先开会再分发）；超级组织让"沟通发生在哪里，执行就发生在哪里"。
- 用 [[智能体编排]] 让 Agent 接管过去依赖产品经理、项目经理、中层的转译协调工作，直接调用工具写代码/做 PPT/做网站。
- 每次沟通被 Agent 记录成"核心提示词"；要求程序员"不写一行代码"，全用自然语言交互。
- 结果：组织极扁平化，人类核心角色或只剩"系统设计师"和"全栈工程师"；项目上线据称从一周缩短到最快 28 分钟。

## 真正的瓶颈：组织采用率

- 成本管理从"管人"变成"管 token 消耗"（称 token 成本约占人力成本 15%）。
- 第一道门槛不是模型能力、功能或价格，而是**组织采用率**："哪怕免费给用，也只有 10%~20% 的人先用起来。"
- 落地需要 CEO 足够坚定，知识型公司、员工已有 AI 习惯。"选择这条路，就没有回头路。"

## 与已有判断的关系

- 与 [[麦肯锡：AI 时代，旧的敏捷开发方式正在拖累个人效率]] 高度互证：个人提效（几小时变几分钟）≠ 公司级提效（常只有 5%-15%），瓶颈在旧流程、协作与采用，而非生成速度。
- 是 [[AI原生组织]] 在中国的扁平化实践样本；与 [[一人公司]]（组织规模→1）构成两条不同路径：一个把人压到 1，一个在组织内用 Agent 重构中间层。
