# 技能原子

> Daniel Cook 把「玩得爽」拆成四步闭环：动作、模拟、反馈、建模。四个步骤连成一次学习，多次学习串成技能链，技能链的堆叠就是玩家的整个成长体验。

## 原始出处

Daniel Cook（网名 Danc）是 Lost Garden 博客作者，曾任 Spry Fox 首席创意官（Triple Town、Alphabear）。核心文章 *The Chemistry of Game Design* 发表于 2007 年。他的写法借鉴化学：把玩家体验当成由更小单元化合而成的化合物，试图找到「最小可设计单元」。

这个框架在业界流传极广，但注意它是设计实践总结，不是经过实验验证的认知科学模型。

## 四步闭环

| 步骤 | 英文 | 内容 | 设计对应 |
| --- | --- | --- | --- |
| 动作 | Action | 玩家做出一个可执行的操作 | 输入映射、操作手感、可用动作集 |
| 模拟 | Simulation | 游戏系统按规则计算后果 | 数值、物理、AI、判定 |
| 反馈 | Feedback | 系统把结果呈现给玩家 | 表现层、音效、镜头、数值变化 |
| 建模 | Modeling | 玩家在脑中更新对系统的理解 | 心智模型、策略形成 |

关键在第四步：建模发生在大脑里，设计师无法直接写入，只能通过前三步的可靠性去影响它。这就是为什么「反馈不清晰」是比「数值不平衡」更严重的问题——反馈不清会导致建模失败，玩家学不到任何东西。

一个闭环跑完，玩家获得一次「我明白了」。这个瞬间的密度，决定游戏的手感是否「有嚼头」。

## 技能链

单个原子太细，玩家实际体验的是一串原子按顺序解锁。Cook 称之为技能链（skill chain）：

低阶技能 → 掌握 → 解锁高阶技能的前置条件 → 再掌握

例子（动作游戏）：闪避 → 闪避取消攻击 → 精确闪避触发反击 → 反击衔接连段。每一环都要求前一环已经成为肌肉记忆，否则高阶技能无法被真正使用。

技能链的设计含义：

- 长度决定深度。链越长，玩家的成长空间越大，但入门门槛越高。
- 断裂决定流失。某一环太难或反馈太差，整条链断在这里，后续内容全部失效。
- 宽度决定风格。横向并行的多条链产生 build 多样性。

## 四种玩家状态

Cook 用这套模型解释留存，把玩家状态分成四类：

| 状态 | 特征 | 设计含义 |
| --- | --- | --- |
| 精通（mastery） | 技能链仍在延伸，学习持续发生 | 目标状态 |
| 早期倦怠（early burnout） | 链太陡，卡住学不动 | 新手流失的主因 |
| 晚期倦怠（late burnout） | 链已走完，无新东西可学 | 老玩家流失的主因 |
| 不活跃（inactive） | 未进入任一链 | 未转化 |

这个分类比「新手/中期/后期」更有用，因为它给出的是原因而非阶段标签。对应解法也不同：早期倦怠要降阶梯或加反馈，晚期倦怠要开新链（新玩法、新角色、新难度层），而不是加内容量。

## 学术界的批评

需要明确标注，避免把这个框架当成定论：

- 隐性知识问题：真正的专家技能大量是 tacit knowledge（默会知识），无法被拆成显式步骤，「原子」的边界是设计者的主观切分。
- 对策略游戏解释力弱：4X、卡牌、模拟经营的核心乐趣来自长周期规划与组合爆炸，不是毫秒级动作-反馈闭环。
- 缺乏实测：四步闭环没有被认知科学实验直接验证过，它是从优秀游戏中反向归纳的。
- 与行为主义的边界模糊：它描述的是可观察的行为-反馈循环，对「意义」「叙事认同」等高层动机无解释力。

因此正确用法是：用它诊断动作层与系统层的可学性，不要用它解释全部乐趣。

## 与 MDA 的互补

[[MDA框架]] 描述整体结构（机制→动态→体验），技能原子描述微观机制（动作→建模）。两者的接缝在「动态」层：技能原子跑起来产生的行为模式，就是 MDA 里的 dynamics。

实践中常见的组合诊断：体验不对 → 用 MDA 定位是哪一层的问题；确认是「学不会」→ 用技能原子找断在哪一步。

## 具体案例

### 马里奥的跳跃：Cook 写的完整一次循环

这是原文里最细的一段观察，值得逐句还原：玩家按下按钮，Mario 弹起，于是形成一个「按按钮会跳」的心智模型。但这个模型常常需要循环两三次才成立——第一次只隐约觉得发生了什么，第二次再按又弹起，此时玩家会微笑，因为他意识到自己刚获得了一个可能有用的小技能。

获得新技能后，玩家立刻做一件事，Cook 称之为 play：新手掌握跳跃后，几乎马上在关卡里到处乱跳，撞到平台，可能爬到顶。这个看似无意义的行为，其实是玩家在测试新技能的边界——它在哪些地方有用，在哪些地方失效。

### Koopa：一个靠前置技能成立的设计

Project Horseshoe 2007 的报告《Smashing the game design atom》里举了 Koopa（乌龟）的例子：想杀 Koopa，你得踩它；而要踩它，最好已经掌握了跳跃。报告的原话是这说明 Miyamoto 多年前就建立了这种经典关系，而「the theory is slowly catching up with the experimentalists」（理论正在慢慢追上那些做实验的人）。

这个案例的价值在于它把「技能链」从一个抽象图变成了一个具体的敌人设计：Koopa 之所以是一个好的第一个敌人，不是因为它弱，而是因为它的解法正好压在前一个原子之上。

### Tetris 的 skill chain 图

Cook 真的为 Tetris 画了一张技能链图（Tetris Skill Chain.pdf）。技能链是一张有向图，原子按前置关系连成网络，整张网络描述整个游戏。他把玩家沿图前进的过程比作 Pac-Man 沿点吃豆。

这张图同时也是这套理论最受争议的地方——见下面的批评。

### 原子的五种状态

| 状态 | 表现 | 设计含义 |
| --- | --- | --- |
| Inactive | 尚未接触 | 需要铺垫与引导 |
| Partial Mastery | 学会了但还不稳 | 需要重复练习的机会 |
| Mastery | 稳定成功，伴随愉悦 | 目标状态，此时应推出下一个原子 |
| Chunked | 已成肌肉记忆，如开车上班 | 不再产生乐趣，需要新链 |
| Burnout | 反复失败后放弃 | 需要降台阶或换路径 |

Chunked 这一态是理解「老玩家为什么流失」的关键：不是内容不够，是技能已经被压缩成无需注意的动作，学习不再发生。

### 尖锐的批评：一次一个原子地做建筑

2007 年 gamedesignreviews 的批评至今仍是最有力的：把人当原子不合理；「Rotating」与「Faster slot recognition」在 Cook 的体系里都叫原子，但前者是顿悟、后者是无法完成，性质完全不同；大量真实技能是 tacit knowledge（骑车、跳探戈无法靠读书学会）；对 Civ、StarCraft 这类策略游戏几乎无效——「用 Cook 的理论分析这个，就像一次一个原子地做建筑」。

最致命的一击是：Tetris 的 skill chain 从未被真实玩家的学习过程验证过，而 Alexey Pajitnov 也不是靠这张图做出 Tetris 的。

### 被真正用起来的地方

- 教育游戏：Echeverría 等用这套框架改造教育物理游戏，把缺失的 skill atom 补齐后，学习效果的统计显著提升。
- 游戏化设计：Deterding 2015 的 gameful design 用它去挖现实活动中潜在的 mini-game。
- 关卡难度：RLD（Rational Level Design，McEntee 2012 / McMillan 2013）在难度平衡上广泛使用这套拆解。

这三处应用的共同前提是：**先由专家手工拆解，再验证效果**。可复现性低仍是它的软肋。
