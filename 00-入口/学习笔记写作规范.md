# 学习笔记写作规范

`02-视频笔记` 里的笔记不是速览卡片，而是严肃学习笔记。目标是让人过一段时间回来读，仍然能回想起视频的主要内容、论证路径、关键例子和可复用知识。

## 目标

- 尽量还原内容本身的展开顺序，不把长视频压成几句空泛结论。
- 同时保留总纲、章节结构、具体论证、关键案例、术语解释和可复用判断。
- 正文直接写内容，不写“视频说”“视频想表达”“这里的重点是”“这个开场故意”这类元叙述。
- 批注、质疑、延伸和我的判断必须单独放在学习批注区，不插进正文打断阅读。
- 事实没有核验时，不写成确定事实；放入待核验区。

## 长视频处理

- 超过 30 分钟的视频必须按章节或时间段拆分。
- 每个章节都要有时间锚点，例如 `[00:12:30]`。
- 一小时左右的视频，通常至少需要 5-8 个章节；内容复杂时可以更多。
- 章节笔记不能只写摘要，要写清楚这一段提出了什么问题、用了什么例子、如何推理、得出什么判断。
- 如果转录很长，可以让多个 agent 按时间段分别整理，再由合并编辑统一口吻和结构。

## 推荐结构

```markdown
# 标题

## 0. 这节课在讲什么

## 1. 章节导览

## 2. 逐段内容笔记

## 3. 核心概念

## 4. 论证链条

## 5. 学习批注

## 6. 可复用知识

## 7. 原文依据

## 8. 待核验
```

## 内容密度

- 短视频可以精炼，但不能只剩结论。
- 长访谈、课程、演讲要保留足够细节：人物观点、问题背景、概念差异、例子、反驳、转折和结论。
- 摘要要服务于回忆，不替代正文。
- 不追求事无巨细记录每句话，但要保证读者能理解内容如何一步步成立。

## 口吻

- 正文使用内容直述，例如“AI 原生公司的核心变化是组织从人工流程转向智能闭环”。
- 不写“视频认为 AI 原生公司的核心变化是……”。
- 学习批注可以写判断，但要明确与正文区分。
- 不随意夸赞、贬低或评价讲述者；只在批注中讨论观点的启发、限制和待验证处。

## Git 与 Obsidian

- 最终进入 Git 的只有 Obsidian vault：`视频知识库`。
- 原始视频、音频、转录、模型、缓存、工具、运行记录都留在外层工作台，不进 vault。
- 每次新增笔记后，要更新入口索引或相关主题页，并提交推送到 GitHub。
