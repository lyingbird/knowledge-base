## 0. 这节课在讲什么

这是一场围绕一线模型研究、AI 公司组织形态、个人路径与技术预测展开的长访谈。姚顺宇以理论物理转向 AI 的经历为背景，串起了几个核心判断：头部模型公司的纸面 benchmark 已经接近打满，接下来更难的是定义值得下注的问题；coding 是当前最 AI 原生的应用场景，因为 reward signal 清楚、数据基础深厚；长上下文、ML coding、自我实验闭环会成为未来几个月到一年内的重要方向；AI 研究的个人英雄主义正在被集体工程、组织执行和基础设施吸收。

整场内容并不只是技术预测，也是一套研究方法论：判断一个问题是否良好定义，遇到异常时系统性排除 bug，在不确定中选择能学习最多的困难位置，在公司环境里把个人项目责任升级为组织责任。最后落到对人的判断：聪明不再稀缺，靠谱、细致、能和 AI 协作并理解自己交付物的人更稀缺。

## 1. 逐段内容笔记

### 1.1 两个姚顺宇、物理背景与进入 AI 的动机 [00:01:27-00:05:19]

嘉宾先区分了同名的另一位姚顺宇：另一位长期做计算机相关工作，他自己则是半道转入 AI。本科在清华做理论凝聚态，后来到斯坦福做高能理论和量子引力、黑洞相关方向，短暂做过伯克利 postdoc 后加入 Anthropic，之后进入 Google DeepMind/Gemini。

离开 Anthropic 时，他没有优先选择能否领导项目，而是把“学习一些不一样的东西”放在前面。这个选择贯穿后文：他多次把难度、陌生性、能否学到新东西作为路径判断的核心，而不是单纯追求位置、名头或个人项目归属。

### 1.2 AI 进入“问题定义”阶段，而不是“能不能做到”阶段 [00:05:36-00:10:08]

他不太认可“上半场/下半场”这种分法，更清楚的变化是：一年前头部实验室还会担心 reasoning、coding 等能力是否追得上；现在 Gemini、OpenAI、Anthropic 三家已经不太担心“能不能做得到”，更难的是“要做什么”和“怎样定义想要的行为”。

公开 benchmark 上，SWE-Bench 等指标已经让头部模型非常接近，80% 附近的一两个点差异更像噪声而不是信号 [00:07:38]。但用户体验仍能感到差异：Claude 偏 agentic 工具使用，Codex 在纯 coding 上追近，Gemini 在纯 reasoning 和日常使用上表现更强 [00:08:08]。差异从“纸面能力”转向“产品意愿、数据、基础设施和行为定义”。

### 1.3 OpenCloud、Minus 与 AI 原生产品形态 [00:11:13-00:19:40]

OpenCloud 的重要性不在于技术突然突破，而在于展示了长链条、多模型协作、long horizon 工作流的可能性。类似能力在实验室内部并不陌生，只是没有被认真打磨为产品公开发布 [00:11:37-00:12:15]。

他没看明白 Minus 和 OpenCloud 的本质差异 [00:14:20-00:14:38]，这反过来说明很多产品爆发来自时机、打磨和传播，而不只是底层模型能力。AI 原生应用目前最明确的是 agentic coding；Chatbot 更像搜索延伸。对“壳公司”来说，模型公司进入应用层会制造压力；但如果市场足够小、足够垂直，模型公司也可能无暇亲自做。

### 1.4 Long horizon：有限上下文训练，无限上下文使用 [00:23:40-00:25:17]

他反复强调的口号是：train with finite context, use as infinite context [00:23:47]。目标不是简单把 context window 拉长，而是让模型在使用中持续交互、不断接收新信息、丢弃不重要内容、保留关键状态，接近理想个人助手的形态 [00:24:17]。

目前尚未形成技术共识，可能有多条路线同时尝试：预训练侧可以通过长上下文训练、稀疏注意力等方式推进；后训练侧可以通过 context management，让模型学会选择、压缩、保存和检索信息 [02:45:00-02:45:21]。他个人更偏向后训练路线，因为这更符合“短 context 训练、长 context 使用”的哲学 [02:45:48-02:46:31]。

### 1.5 预训练没有明显撞墙，撞墙常常是 bug 或假设问题 [00:25:17-00:31:57]

模型进步是否变慢取决于评价标准。单个 benchmark 越接近满分，分数增长当然会放缓，但这不必然意味着用户体验或模型学习能力变慢 [00:25:49-00:26:19]。他自己的体感是预训练仍在增强，未来四个月也没看到到头迹象 [00:27:20]。

“撞墙”可能来自三类原因：规律本身适用范围到头；关键条件无法满足，比如数据不够；工作里有 bug 或科学假设没选对 [00:27:52-00:29:25]。第三类在他观察中最常见。修好一个 bug 带来的进展，可能远大于某些看似神奇的技巧。真正关键的是系统性：当实验结果与预测不一致时，能否通过 ablation 逐项排除因素，确认哪些假设真的有效 [00:29:56-00:30:56]。

### 1.6 Coding 为什么发展最快 [00:35:03-00:47:06]

Coding 有两个天然优势。第一，reward signal 良好定义：写一个 feature，给定输入应得到输出，测试能判断实现是否成功 [00:35:33-00:36:35]。第二，GitHub 汇聚了几十年优质代码，可以构建大量训练环境；相比普通网页，代码数据质量更高 [00:36:35-00:37:07]。

产品层面，优秀代码有相对稳定的共识标准：简洁、干净、结构清楚、抽象合理、适合未来开发 [00:37:37-00:38:08]。他自己的代码中，保守估计 90% 由模型产生，不保守估计可到 99% 或 100%；人的工作重点转为设计逻辑、提供上下文、审查代码是否真符合目标 [00:38:40-00:39:40]。研究实验的实现效率相较一年前可能提高 20 到 50 倍 [00:41:11]。

程序员被取代不是一夜之间发生，而是渐进过程；部分公司裁员已经体现了这种趋势 [00:46:37-00:47:06]。相反，好的产品经理暂时更难训练出来，因为“好产品”的反馈信号不清楚，必须放到真实用户中才知道 [00:46:02-00:46:35]。

### 1.7 中国模型、蒸馏与 multi-agent 训练 [00:53:30-00:57:04]

从过去一年到一年半看，中美模型能力差距在缩小 [00:53:39-00:53:50]。中国实验室在算力限制下对蒸馏更加熟练。直接从 Claude 等模型取 token 再训练属于“硬蒸”，在商业上不道德，在治理上也愚蠢，因为它说明公司没有自己的方向，只是在抄别人 [00:55:00-00:55:43]。

另一类“聪明蒸馏”更复杂：在生成数据链条中使用别家模型作为辅助，或把别家模型当评价者 [00:55:49-00:56:13]。这在商业上处于灰色地带，但技术上很有意思，因为不同模型分布不同，把多家模型融进训练系统，反而接近真正的 multi-agent 训练 [00:56:20-00:56:50]。

### 1.8 从物理到 AI：难题、可验证性与“老灯”问题 [01:08:50-01:40:00]

个人经历部分展示了他长期选择困难环境的倾向。高中阶段在上海四校普通班和格致中学竞赛班之间，他选择后者，理由是“光脚的不怕穿鞋的” [01:12:00-01:12:07]，更深的动机是想体验没做过、确实难的事。

本科的非厄米系统研究来自开放量子体系：真实系统往往不是孤立系统，哈密顿量不一定是厄米矩阵，传统 Bloch 波假设会失效 [01:23:18-01:24:07]。物理学里的重整化群提供了一个重要思想：同一个体系在不同能量尺度下可能呈现完全不同的有效理论，经典物理和量子物理也是不同尺度上的描述 [01:30:00-01:30:59]。

博士阶段的高能理论给他的教训是：困难本身不够，困难必须可验证。高能理论在实验完全追不上的尺度上推进，客观评价标准不足，领域判断容易依赖资深权威和主观品味 [01:36:56-01:38:04]。这也解释了他后来反复强调“良好定义”和“客观 reward signal”。

### 1.9 Anthropic、后训练与组织执行 [02:01:00-02:20:32]

Anthropic 的一个优势是 reactive：能快速捕捉内部和市场信号，并扑上去执行 [02:01:00-02:01:22]。top-down 能跑起来，需要技术决策人同时也是公司决策人：既能在技术上服众，又能为公司承担责任 [02:01:30-02:02:05]。

Claude 3.7 被他视为 Anthropic 后训练的分水岭。此前后训练更像小规模修补；之后大家逐渐意识到后训练可以 scale up：找到合适环境，确保 reward signal 清楚，同时把环境本身作为强数据源 [02:12:20-02:13:05]。

他对“技术 tips”的态度很谨慎。很多算法设计强依赖基础设施，例如 RL 中 sample 机器和 trainer 机器可能由于数值差异、异步训练架构等原因不一致，不同公司这种不一致的程度也不同，因此算法 trade-off 很难脱离 infra 复制 [02:19:24-02:20:32]。真正的 know-how 在细节、平衡和稳定路径选择中。

### 1.10 英雄主义、ML coding 与 Gemini 的下一步 [02:30:00-03:11:15]

模型侧更像集体主义：AI 方向很多 idea 并不稀缺，关键在于集体能否围绕目标投入时间和精力 [02:30:00-02:30:44]。他认为如果没有 Anthropic 做 coding，别的公司也会做；AI 是浪，个体只是赶上浪尖的人 [03:05:18-03:05:52]。个人英雄主义在模型研究员层面减弱，但在产品方向、组织下注和技术一号位上仍可能存在。

Gemini 阶段的主要工作集中在 ML coding 和 long horizon [02:41:13-02:41:30]。ML coding 指让 AI 自己研究自己：写代码、跑实验、看结果、分析、提出新假设、设计新实验。大方向有共识，难点在数据、反馈信号和基础设施细节 [02:41:31-02:42:01]。

公开 benchmark 的关注价值下降。SWE-Bench 80 多分附近已经接近打满；ARC-AGI 从早期十几分到 Gemini 3 的三十多、Claude 4.6 的六十多、Gemini 3 DeepThink 的八十多，也进入公众认知层面的打满状态 [03:07:13-03:08:30]。接下来更重要的是找到新的、良好定义的目标。

continuous learning 与 long horizon 在他看来没有本质区别：传统上 continuous learning 改模型权重，context management 不改权重；但 context 中 token 的 KV cache 也可以看作一种权重 [03:10:40-03:11:11]。

### 1.11 组织责任、技术领导与 AI 时代招聘 [03:18:01-03:33:08]

公司里的研究员不能只为自己的项目负责，还要为公司整体负责 [03:18:01-03:18:21]。这种责任感未必来自宏大价值观，也可以只是“拉不下脸”：对公司负责是契约的一部分，没有什么道理不这么做 [03:18:25-03:18:40]。如果只是为了个人英雄主义而做事，很可能破坏整体性 [03:18:51-03:18:58]。

好的技术领导需要两种能力：一是救火能力，真遇到困难时能下场带人解决；二是理解别人，哪怕自己不做那件事，也能理解别人为什么做、为什么重要 [03:20:01-03:21:15]。最好的组织状态往往不稳定，需要领导维持不塌缩 [03:20:16-03:20:23]。

他提出一种 AI 时代的面试方式：给候选人 24 小时，让其用 AI 从 0 到 1 完成一个 RL 项目，然后进行一小时讨论 [03:32:01-03:32:14]。考察重点不是传统写代码能力，而是能否有效利用 AI、能否理解 AI 做了什么。全盘扔给 AI 而不理解，会在讨论里露馅 [03:32:30-03:33:08]。

## 2. 核心概念

- **良好定义**：问题、行为或评价标准足够清楚，能够被训练、测试或证伪。AI 当前竞争从“能不能做”转为“能不能定义清楚要做什么”。
- **Reward signal**：训练或评估中判断结果好坏的反馈信号。coding 的反馈信号相对清晰，产品经理和好产品的反馈信号则模糊。
- **Long horizon**：模型处理长周期任务、长期交互和跨上下文状态管理的能力。
- **Train with finite context, use as infinite context**：用有限长度上下文训练，但在使用时通过选择、压缩、保存、检索等机制支持接近无限上下文。
- **ML coding**：让 AI 参与机器学习研究闭环，包括写实验代码、跑实验、读结果、分析失败、提出下一步假设。
- **Post-training / 后训练**：预训练之后通过环境、反馈信号、RL、SFT 等方式塑造模型行为。Claude 3.7 被视为 Anthropic 后训练规模化的分水岭。
- **Distillation / 蒸馏**：使用其他模型输出或评价能力来训练自身模型；硬蒸直接抄 token，聪明蒸馏把其他模型嵌入数据生成或评价链条。
- **Context management**：让模型在上下文中选择保留、丢弃、写入外部文件或检索信息，是后训练实现 long horizon 的重要路线。
- **3D Torus TPU 互联**：TPU 以三维 torus 连接大量卡，放弃小 pod 内两两高速互联，换取大规模集群上的存储与通信优势 [03:22:00-03:23:08]。
- **Reliability contract**：把对组织负责理解为契约，而不只是道德姿态。靠谱、细致、能对交付负责，是 AI 时代更重要的人才特质。

## 3. 论证链条

1. 公开 benchmark 逐渐打满，头部模型纸面能力接近。
2. 纸面差异缩小后，真正的竞争转向问题定义、产品形态、数据构建、基础设施与组织下注。
3. Coding 能先跑出来，是因为它同时拥有清楚 reward signal 和高质量历史数据；因此它成为 AI 原生应用的第一块高地。
4. 当 AI 能写大部分代码，人类价值从“手写实现”转向“定义任务、提供上下文、审查结果、理解系统”。
5. Long horizon 与 ML coding 是下一阶段下注方向：一个解决长期上下文和个人助手问题，一个让 AI 加速 AI 研究自身。
6. 这些方向都不是单个天才 idea 能解决，而是需要大规模工程、实验系统、ablation、基础设施和组织执行。
7. 因此研究员级个人英雄主义下降，技术领导、组织责任、可验证问题定义和可靠协作能力上升。
8. 个人层面的行动结论是：别迷信“聪明”，要训练自己把问题定义清楚，能和 AI 协作完成端到端任务，并在复盘中讲清每个选择。

## 4. 学习批注

“良好定义”是贯穿整场的钥匙。它既解释了 coding 为什么先爆发，也解释了高能理论为什么让他失望，还解释了 benchmark 为什么会失效：不是能力增长停止，而是原有评价器不再能分辨真实差异。

他对预训练未撞墙的判断很有启发，但置信度应放在“大模型实验室视角”里理解。资源、数据、工程体系足够强时，bug 和假设错误确实常常被误读为天花板；对资源受限团队来说，硬约束也可能真实存在。

“个人英雄主义已过去”需要分层理解。模型研究中的个人署名变弱，集体工程更重要；但能定义方向、调动组织、为技术路线负责的领导者反而更关键。不是英雄消失，而是英雄的位置从“单点发明者”迁移到“技术与决策权合一的人”。

24 小时 AI 协作面试很适合作为自测：把一项陌生任务交给 AI 协助完成，然后检查自己能不能解释目标、数据、代码、失败原因和下一步。AI 时代的“会用工具”不等于“把任务扔出去”，而是能保持理解权和责任权。

## 5. 可复用知识

- 判断研究方向：先问目标是否良好定义，能否构建清楚反馈信号，失败后能否做 ablation。
- 判断 AI 产品机会：优先寻找 reward signal 清楚、数据基础深、用户对“好”的共识较强的场景。
- 使用 AI 写代码：人负责设计逻辑、给上下文、验收质量、理解产物；模型负责生成大量实现。
- 做实验：结果不符合预期时，不急着宣布规律失效，先排查数据、假设、实现、infra 和评估 bug。
- 选职业路径：难度本身不是理由，值得选择的是能学习、可验证、能积累能力的难题。
- 建团队：技术 leader 至少要能救火、能理解别人，并拥有足够决策权来承担组织级后果。
- 招人或自测：端到端任务加限时交付加深度复盘，比传统代码题更能测出 AI 协作能力与可靠性。
